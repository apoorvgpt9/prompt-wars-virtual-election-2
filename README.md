# ElectEd — AI-Powered Indian Election Literacy Platform

> **Empowering Citizens through Election Literacy**

ElectEd is a structured, AI-driven educational platform that guides citizens through the Indian election process — from voter registration through ballot counting — using a multi-agent Gemini workflow, scenario-based quizzes, and a fully accessible, stage-managed UI.

---

## Chosen Vertical

**Civic Education / Indian Election Literacy**

The vertical is hyper-specific: explaining India's election process as governed by the **Election Commission of India (ECI)**. Every piece of content generated by ElectEd is constrained to this domain — topics such as the Model Code of Conduct (MCC), Electronic Voting Machines (EVMs) and VVPAT, Voter Registration (Form 6), Lok Sabha and Vidhan Sabha constituency rules, polling booth procedures, and result counting.

This vertical was chosen because:
- Election literacy is a measurable public good — informed voters make better democratic choices.
- India's election system has significant complexity (ECI guidelines, MCC enforcement, EVM procedures) that benefits from AI-assisted explanation.
- The domain is safe and deterministic enough to enforce strict AI governance (the model cannot drift into political opinion or speculation).
- It maps naturally to a workflow tool (topic → analysis → modules → quiz → feedback) rather than an open-ended chat interface.

---

## Approach and Logic

### Architectural Philosophy: Workflow Tool, Not Chat

ElectEd deliberately avoids a chat interface. Users click and select — they don't type free-form conversations. This design decision:
- Reduces off-domain input dramatically (structured selectors replace text boxes where possible).
- Keeps the UI stage-managed and predictable (`idle → analysing → building → learning → evaluating → feedback`).
- Makes accessibility and keyboard navigation tractable by keeping the DOM state machine small and deterministic.

### Multi-Agent Orchestration

Three specialised AI agents operate in sequence, each with a dedicated API route and system prompt:

```
User selects topic
        │
        ▼
 ┌─────────────┐
 │  /api/analyse│  → ANALYST agent: decomposes topic into problemArea,
 │  (Agent 1)  │    keyDimensions, userContext, complexity level
 └──────┬──────┘
        │ AnalystOutput (JSON, Zod-validated)
        ▼
 ┌─────────────┐
 │  /api/build  │  → BUILDER agent: creates 4 modules + 6-8 step timeline
 │  (Agent 2)  │    from the analyst output
 └──────┬──────┘
        │ BuilderOutput (JSON, Zod-validated)
        ▼
 User reads modules, selects one, attempts quiz scenario
        │
        ▼
 ┌─────────────────┐
 │  /api/evaluate   │  → EVALUATOR agent: assesses user's quiz answer,
 │  (Agent 3)      │    returns feedback + encouragement + nextStep
 └─────────────────┘
```

Each agent receives the output of the previous stage as context, enabling compounding intelligence: the builder's modules are grounded in the analyst's dimensional decomposition, and the evaluator's feedback is grounded in the exact quiz scenario shown to the user.

### Governance Pipeline (Every Request)

Every API call enforces a strict pipeline:

```
Request Body
    │
    ▼ Zod schema parse (400 on failure)
    │
    ▼ validateInput() — sanitize HTML, check length, check prompt injection, check domain keywords
    │  (400 on failure)
    │
    ▼ callGemini() — system prompt includes GOVERNANCE_CLAUSES
    │
    ▼ validateOutput() — parse JSON, check for OUT_OF_DOMAIN / UNSAFE_INPUT signals, field length caps
    │  (502 on failure, 422 on out-of-domain)
    │
    ▼ Return typed, validated response
```

No raw AI output ever reaches the client without passing this chain.

### Key Components in Detail

#### `lib/governance.ts` — The Safety Contract
`validateInput` is the Layer 1 gate. It:
1. Strips HTML tags via regex.
2. Enforces min 3 / max 200 character length independently of the Zod schema (defence-in-depth).
3. Runs prompt injection detection against known patterns (`ignore previous`, `system:`, triple backticks).
4. Validates domain relevance using a comprehensive election keyword regex covering 30+ ECI-specific terms.

`validateOutput` is the Layer 3 gate. It:
1. Strips markdown code fences (`\`\`\`json`) before parsing — models occasionally wrap JSON.
2. Detects structured error signals (`OUT_OF_DOMAIN`, `UNSAFE_INPUT`) that agents return when they refuse a query.
3. Caps individual field lengths at 1000 characters to prevent runaway AI text.

#### `lib/gemini.ts` — Resilient API Client
- Uses `gemini-3-flash-preview` exclusively (enforced in GEMINI.md).
- Implements exponential backoff retry (2s, 4s, 8s) for 429 / 503 / RESOURCE_EXHAUSTED responses.
- Supports both one-shot (`callGemini`) and streaming (`streamGemini`) invocation.
- Uses `AbortController` + `setTimeout` for 30-second request timeout.
- System prompts and user content are structurally separated using Gemini's `systemInstruction` and `contents` fields — prompt injection cannot override the instruction layer.

#### `lib/prompts.ts` — Centralised Prompts
All system prompts are named exports — never inline strings inside route handlers. Every prompt:
- Receives `DomainConfig` to maintain domain-agnostic prompt logic.
- Appends `GOVERNANCE_CLAUSES` — five non-negotiable rules restricting the model to ECI-accurate, politically neutral, India-specific content.
- Specifies exact JSON response schemas to maximise structured output reliability.

#### `components/election-timeline.tsx` — Visual Process Map
Renders the election process as a true visual timeline: numbered circles connected by a vertical line, with key milestones highlighted in the primary brand colour. Never rendered as a bullet list (enforced via AGENTS.md rule).

#### `app/page.tsx` — Stage Machine UI
Six distinct UI stages managed via a single `stage` state variable. Each stage transition is driven by successful API responses — no optimistic state skipping. `aria-live="polite"` regions and `ref.current?.focus()` ensure screen readers announce content updates after each AI call.

## Assumptions Made

### Content & Domain
1. **ECI as ground truth.** All election facts are assumed to be accurately described by the Gemini model when constrained to ECI-accurate governance clauses. The platform is educational, not legally authoritative.
2. **Indian English locale.** All UI copy, domain terminology (Lok Sabha, VVPAT, Form 6), and AI content targets Indian English speakers.
3. **Topics are pre-seeded but open.** The `StructuredInput` component offers five preset topic chips (MCC, EVM Security, Voter Registration, Polling Station Rules, Counting Process), but users may type custom topics. Domain gate enforced at API level regardless.
4. **4 modules per learning journey.** `ACTIVE_CONFIG.moduleCount = 4` is a deliberate UX choice — enough depth without overwhelming a first-time user.
5. **6–8 timeline items.** The Builder is constrained to produce between 6 and 8 election process steps, ensuring the visual timeline is always substantive but never unwieldy.

### Technical
6. **Server-side API key only.** `GEMINI_API_KEY` is never available client-side. All Gemini calls route through Next.js API routes. This is a hard architectural constraint, not a best-effort guideline.
7. **In-memory rate limiting.** The rate limiter uses a `Map` — not Redis or a distributed store. This means rate limits are per-instance and reset on serverless cold starts. Acceptable for a demo/MVP; a production system at scale would use Cloud Memorystore.
8. **No authentication.** ElectEd is a public-facing civic education tool. No login or user accounts are required or implemented.
9. **Standalone Next.js output.** `output: 'standalone'` in `next.config.mjs` is required for the multi-stage Docker build to produce a minimal, self-contained production image without shipping `node_modules`.
10. **Non-root container user.** The Docker runner stage creates a dedicated `nextjs` system user (uid 1001) and runs the process under that user — standard container security hardening.

### Testing
11. **Gemini always mocked in tests.** `vi.mock('../lib/gemini')` is applied to all API route tests. No real API calls are made during `npm test`. Governance and validation tests are fully deterministic (no mocking needed — they test pure functions).
12. **TypeScript strict mode.** `tsconfig.json` enables strict TypeScript. `any` types are prohibited per AGENTS.md. All Zod schemas export inferred TypeScript types (`AnalystOutput`, `BuilderOutput`, `EvaluatorOutput`).

## Running Locally

```bash
# 1. Install dependencies
npm install

# 2. Set your API key
cp .env.example .env.local
# Edit .env.local and add: GEMINI_API_KEY=your_key_here

# 3. Start the dev server
npm run dev
# → http://localhost:3000

# 4. Run tests
npm test

# 5. Lint check
npm run lint
```

## Running with Docker

```bash
docker build -t elected .
docker run -p 3000:3000 -e GEMINI_API_KEY=your_key_here elected
# → http://localhost:3000
```

## Deploying to Cloud Run

```bash
# Build and push to Artifact Registry
gcloud builds submit --tag gcr.io/PROJECT_ID/elected

# Deploy to Cloud Run (asia-south1)
gcloud run deploy elected \
  --image gcr.io/PROJECT_ID/elected \
  --region asia-south1 \
  --platform managed \
  --allow-unauthenticated \
  --set-env-vars GEMINI_API_KEY=your_key_here
```

## Evaluation Criteria Mapping

| Criteria | Implementation |
|---|---|
| **Code Quality** | TypeScript strict mode throughout; JSDoc on all exported functions; kebab-case components, camelCase lib files; no `any`, no `var`; single-responsibility modules |
| **Security** | 6 HTTP security headers (CSP, HSTS, X-Frame-Options, etc.); server-side API key only; prompt injection detection; Zod schema validation + independent input sanitisation; in-memory rate limiting; non-root Docker user; no stack traces in API error responses |
| **Efficiency** | Exponential backoff retry prevents thundering-herd on Gemini throttling; `output: standalone` Docker build minimises image size; in-memory rate limiter with O(n) cleanup on each request; streaming API available for long-form content |

| **Google Services** | Gemini API (`gemini-3-flash-preview`) powers all three agents; CSP explicitly scopes `connect-src` to `generativelanguage.googleapis.com`; deployed on Google Cloud Run (`asia-south1`) via Cloud Build |
